EXP-03 · work

A promotion process as a state machine

A promotion workflow as explicit stages with guards, and a history that is only ever appended to.

Question
Can a promotion process with employees, managers and a committee stay correct as cases move through it?
My part
Designed and built it end to end; planned and broke down most of the work myself.
Decision
Model the process as a stage engine with table-driven tests, and never rewrite a case's history.It cost · Every new rule needs new rows in the test tables; a correction is a new entry, not an edit.
Result
  • Designed and built end to end: data model, backend, jobs and frontend.
a working miniature with every case, for the curious

The record

Context

Promotion requests pass through several people and stages and must keep a trustworthy history.

Setup

  • Data models and a stage engine covered by table-driven tests.
  • An append-only case history, so past decisions are never rewritten.

Method

  • Employee requests, manager decisions with written justification, committee review and a guarded publish of the final result.
  • A daily sync job and an integration with the HR/ERP career ladder.
  • Planned and broke down most of the work myself.

Side effects

Sees state machines everywhere now, including the coffee machine.

Instruments

Node.js · Fastify · MongoDB · TypeScript · React
