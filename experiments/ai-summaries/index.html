EXP-01 · work

AI summaries people can review

LLM summaries of evaluation feedback, generated in a queue and shown only after a person approves them.

Question
Can an LLM summarise many pieces of evaluation feedback in a way people can trust and control?
My part
Sole author of the backend (8 endpoints, 3 data models); also built its admin generation and approval screens.
Decision
Generate summaries through the existing job queue, and publish one only after a person approves it.It cost · Summaries are not instant, and someone has to review each one before anyone else sees it.
Result
  • 383 automated tests on the backend feature.
  • A first version shipped to production; the lifecycle refactor is merged.
a working miniature with every case, for the curious

The record

Context

Evaluations collect many free-text feedback items. Reading all of them is slow; an unreviewed AI summary is risky.

Setup

  • Feedback summaries generated asynchronously through a job queue, so the user interface never waits on a model.
  • A publish/unpublish lifecycle and versioned history, so a person decides what is shown.
  • Bulk generation with quota and overlap guards.

Method

  • Wrote the backend as its sole author and built the admin generation and approval frontend.
  • Evaluated LLM providers on output quality, cost, availability and API reliability for Persian-language use.

Side effects

Developed strong opinions about versioned history.

Related

A separate feature: an in-editor assistant that suggests SBI-format (situation, behaviour, impact) feedback with next actions.

Instruments

Fastify · MongoDB · BullMQ · LLM APIs · React · TypeScript
